# Agent Guidelines for Linux Command Of the Day

## Build/Run Commands
- No build step required - static HTML/CSS/JS project
- Serve locally: `python3 -m http.server 8000` or open `index.html` in browser
- Generate data: `./create_commands.sh && ./collect_en.sh` (requires Python 3)
- No linting or test commands - no test suite exists

## Code Style
- **JS**: ES6+ vanilla JavaScript, no frameworks. Use `const`/`let`, arrow functions, template literals
- **Formatting**: 2-space indentation, no semicolons in JS. Single quotes for strings
- **Naming**: camelCase for JS vars/functions (`todayIndex`, `renderDay`, `shuffleArray`)
- **HTML**: Semantic HTML5, minimal structure. IDs for unique elements, classes for reusable styles
- **CSS**: Global styles in `style.css`, descriptive naming (`.nav-command`, `.example-desc`, `.protip`)
- **Error handling**: Minimal - use `.then()/.catch()` for promises, basic bash checks with `[ ]`
- **Bash**: Use `#!/usr/bin/env bash` shebang, exit on errors, quote variables
- **Comments**: Function-level comments when logic is non-obvious (e.g., seeded shuffle algorithm)

## Data Structure
- Commands stored as `.md` files in `data/` with structure: `# name`, description, `## Examples`, `## Pro tip`
- JSON generated by `collect_en.sh` with format: `{name, description, examples: [{cmd, desc?}], protip}`
- Examples can be strings or objects with `cmd` and optional `desc` fields
- Daily rotation uses seeded shuffle (seed: 12345) based on days since 2025-01-01 UTC

## Project Structure
- `index.html` - Main app entry, PWA manifest
- `script.js` - Daily command rotation, rendering, navigation, share/copy functionality
- `style.css` - Responsive styling, mobile breakpoint at 767px
- `data/*.md` - Command docs (name, description, examples, protip)
- `commands_en.json` - Generated JSON feed (don't edit manually)
- `create_commands.sh` - Generates markdown from command definitions
- `collect_en.sh` - Python script to parse markdown into JSON
